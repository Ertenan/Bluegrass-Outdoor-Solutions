# Project Working Agreement

## Publishing and Git

- Keep all website changes local unless the user explicitly says to commit and push.
- Do not commit, push, or deploy merely because implementation and validation are complete.
- When the work appears ready to publish, suggest committing and pushing, then wait for explicit user approval before doing either action.
- Use conversation context to recognize a likely publishing point, such as completing a checklist, finishing touches, or the user indicating the site is ready.
- Treat requests to edit, fix, build, verify, or preview as local-only unless the user also explicitly asks to commit and push.
- A request to commit without a request to push authorizes only the commit. A request to push authorizes deployment through the repository's existing GitHub Pages workflow.
